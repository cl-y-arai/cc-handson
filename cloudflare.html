Backlog.md を Cloudflare Workers で公開する

「GitHub の fork を Cloudflare につなぎ、main と preview の2つのブランチをそれぞれの URL で公開する」

所要 約30分 Cloudflare Workers Containers GitHub 連携 Preview Access

1概要：何を作るか

Section 3 では、チームで PR を出し合いながら Backlog.md を開発する。この資料では、その変更を ブランチごとにインターネット上の URL で確認できる環境 を Cloudflare Workers に用意する。Backlog.md 環境 の Codespaces が「自分だけが開ける開発環境」なのに対し、こちらは「インターネット上にあり、ログインしたチームのメンバーなら誰でも開ける環境」になる。

ブランチ公開される URLいつ更新されるか
mainhttps://backlog-md.<サブドメイン>.workers.devmain に push（PR をマージ）したとき
previewhttps://preview-backlog-md.<サブドメイン>.workers.devpreview に push したとき

<サブドメイン> は手順2 で決める自分専用の workers.dev サブドメイン。preview 以外のブランチも、push すると <ブランチ名>-backlog-md.<サブドメイン>.workers.dev で公開される（Cloudflare の Worker Previews という機能）。

しくみ

  • Cloudflare の Workers Builds が GitHub の fork を見張り、push されるたびにビルドとデプロイを行う
  • Backlog.md は Bun 専用の API（Bun.serve）とファイルの読み書きを使うため、Workers の実行環境そのものでは動かない。そこで Worker の後ろに Cloudflare Containers のコンテナを置き、その中で bun src/cli.ts browser をそのまま起動する。アプリのソースコードは変えない
  • コンテナはしばらくアクセスが無いと止まり、次のアクセスで数秒かけて起動し直す
  • Backlog.md にはログインの仕組みが無いため、Cloudflare の Access で Worker の前にログインを掛け、許可したメールドメインの人だけが開けるようにする

前提

  • Backlog.md 環境 の手順1 で作った自分の fork（<自分のアカウント>/Backlog.md-handson）
  • fork に Cloudflare 用の設定ファイル（wrangler.jsonc・Dockerfile など）が入っていること。中身は 8章 を参照
  • メールアドレスと、Workers Paid プランの支払いに使うクレジットカード
⚠️ Containers は有料プランが必要 Cloudflare Containers は Workers Paid プラン（月額 5 米ドル） でのみ使える。アカウント作成は無料だが、手順1 で Workers Paid に登録が必要。使い終わったら 10章の手順でプランを解約する。料金の最新情報は Containers の料金ページ で確認する。

2手順1：Cloudflare のアカウントを作成する

dash.cloudflare.com/sign-up を開き、メールアドレスとパスワードを入力して Sign up を押す。

届いた確認メールのリンクを開いて、メールアドレスを確認する。確認が終わるとダッシュボードに入れる。

Workers Paid プランに登録する

ダッシュボード左のメニューで Workers & Pages を開き、Plans（プラン）から Workers Paid を選んで支払い情報を登録する。

💡 画面の表記について Cloudflare のダッシュボードは頻繁に更新される。ボタンの名前や位置がこの資料と違うときは、同じ意味の項目を探す。表示言語は右上のアカウントメニューから日本語にも切り替えられる。

3手順2：ログインして Worker を作成する

dash.cloudflare.com/login からログインし、左のメニューの Workers & Pages を開いて Create application を押す。

初めて Workers を使うときは、workers.dev のサブドメインを決める画面が出る。ここで決めた名前が、公開 URL の <サブドメイン> になる（例：自分の GitHub アカウント名）。

作成方法の一覧から Start with Hello World! を選ぶ。Worker の名前（Worker name）は backlog-md にして Deploy を押す。

デプロイが終わると、https://backlog-md.<サブドメイン>.workers.dev で「Hello World!」が表示される。この中身は手順4 で Backlog.md に置き換わる。次の手順3 で、置き換わる前に認証を掛けておく。

4手順3：Cloudflare Access で認証を掛ける

Backlog.md の Web UI にはログインの仕組みが無く、URL を知っていれば誰でもタスクを見たり編集したりできる。そこで、GitHub と連携して Backlog.md を公開する 前に、Cloudflare の Access（Zero Trust の機能）で Worker 全体にログインを掛ける。ここでは、指定したメールドメイン（例：会社のドメイン）のメールアドレスを持つ人だけ が、メールで届くワンタイムコード（One-time PIN）でログインして開けるようにする。

#やることどこで
3-1Zero Trust の初期設定（チーム名・プラン）Zero Trust
3-2ログイン方法に One-time PIN を追加Zero Trust
3-3Worker に Access を掛け、許可するメールドメインを指定Workers & Pages
3-4ログインできるか確認ブラウザ

3-1. Zero Trust の初期設定

ダッシュボード左のメニューで Zero Trust を開く。初めて開くと初期設定の画面になるので、チーム名 を決める（ログイン画面の URL https://<チーム名>.cloudflareaccess.com に使われる）。

続けてプランを選ぶ画面になるので Free を選び、支払い情報を入力して進める。Free プランでも支払い情報の入力は求められるが、請求はされない。

💡 2段階認証を求められたら Zero Trust を使うには Cloudflare アカウントの2段階認証（two-factor authentication）を有効にする必要がある。求められたら、右上のアカウントメニューの Profile → Authentication から設定する。

3-2. ログイン方法に One-time PIN を追加

新しく作った Zero Trust の組織では、ログイン方法が「Cloudflare のアカウントでログイン」だけになっている。Cloudflare アカウントを持たないチームメンバーもメールアドレスだけでログインできるよう、One-time PIN を追加する。

Zero Trust の画面で Integrations → Identity providers → Add new identity provider を開き、One-time PIN を選んで保存する。

3-3. Worker に Access を掛ける

Workers & Pages に戻って backlog-md を開き、Access タブで Protect this Worker behind Access を選ぶ。次のように設定して Apply Access を押す。

項目設定する値
保護する範囲All traffic（本番の URL と preview の URL の両方。Previews only だと本番の URL が誰でも開けるままになる）
Authentication policyEmail domain を選び、許可するメールのドメインを入力する（例：example.co.jp）
  • Worker に掛けた Access は、workers.dev の URL だけでなく Preview の URL（preview-backlog-md.〜 など）にもまとめて効く。あとから作った Preview にも効く
  • 許可する人を後から変えるときは、Zero Trust の Access controls → Policies で該当のポリシーを Edit し、Include のルール（Emails ending in：ドメイン、Emails：個別のアドレス）を編集して Save する
⚠️ フリーメールのドメインは指定しない gmail.com のようなフリーメールのドメインを指定すると、そのドメインでメールアドレスを作れる 世界中の誰でも ログインできてしまう。会社など、自分たちだけが使うドメインを指定する。チームにフリーメールの人がいる場合は、ポリシーの Include に Emails のルールを足して、その人のアドレスを個別に許可する。

3-4. ログインできるか確認する

ブラウザのシークレットウィンドウで https://backlog-md.<サブドメイン>.workers.dev を開く。Hello World! の代わりに Access のログイン画面が出れば、認証が掛かっている。

  1. 許可したドメインのメールアドレスを入力し、Send login code を押す
  2. メールで届いたコードを入力して Sign in を押す（コードの有効期限は10分。1回しか使えない）
  3. Hello World! が表示されれば成功
⚠️ Web UI の自動更新は効かなくなる Worker の Access タブで掛けた認証は、今のところ WebSocket の接続を通さない（403 になる）。Backlog.md の Web UI は、タスクが変わったことを WebSocket で受け取って画面を自動更新しているため、この構成では自動更新が効かない。最新の状態を見るときはページを再読み込みする。ページの表示やタスクの読み込みは、ソースを見る限り通常の HTTP で行われているので、影響を受けない見込み。

5手順4：GitHub リポジトリを連携する

作成した backlog-md の画面で Settings タブを開き、Build の Git repository にある Connect を押す。

接続先に GitHub を選ぶと、GitHub の画面に移って Cloudflare Workers & Pages という GitHub App のインストールを求められる。Only select repositories を選び、自分の fork Backlog.md-handson だけを指定して Install & Authorize を押す。

Cloudflare の画面に戻ったら、次のように設定して Connect を押す。

項目設定する値
Git account自分の GitHub アカウント
Git repositoryBacklog.md-handson
Branch control（本番のブランチ）main
Enable Preview Buildsチェックを入れる（main 以外のブランチも公開する）
Build command空欄のまま
Deploy commandnpx wrangler deploy（既定値のまま）
Preview commandnpx wrangler preview（既定値のまま）
Root directory空欄のまま（リポジトリのルート）
⚠️ Preview command を wrangler deploy にしない Preview command（main 以外のブランチで動くコマンド）を npx wrangler deploy に変えると、preview ブランチの内容で本番の URL が上書きされてしまう。既定値の npx wrangler preview のままにする。

6手順5：本番の URL で開く

連携が終わると、main の最新コミットで最初のビルドが始まる。Worker の Deployments（または Builds）タブでログを確認できる。始まらないときは、fork の main に何かコミットを push するか、画面の再実行ボタンを押す。

ビルドが成功したら https://backlog-md.<サブドメイン>.workers.dev を開く。Hello World! の代わりに Backlog.md の Kanban Board が表示されれば成功。

⚠️ Web UI での編集は残らない 手順3 の Access で、開けるのは許可したメールドメインの人だけになっている。ただし、ログインした人は Web UI からタスクを編集できる。コンテナのディスクは起動のたびにリポジトリの内容に戻るため、Web UI での編集は残らない（タスクの変更は git でコミットして PR で取り込む）。

7手順6：preview ブランチを preview-〜 の URL で開く

ローカルの clone で preview ブランチを作って push する。

$ git switch main && git pull
$ git switch -c preview
$ git push -u origin preview

push すると Workers Builds が Preview command（npx wrangler preview）でビルドし、ブランチ名を名前にした Preview を作る。ビルドが終わったら次の URL を開く。

https://preview-backlog-md.<サブドメイン>.workers.dev
  • 以後、preview に push するたびに同じ URL の中身が新しいコミットに置き換わる
  • PR を作ると、Cloudflare がビルド結果と Preview の URL を PR にコメントしてくれる。レビューする人はその URL で動作を確かめられる（Access のログインが必要。許可したメールドメインの人だけが開ける）
  • 動作を確認できたら preview → main の PR をマージすると、本番の URL に反映される
💡 Preview ごとに別のコンテナが立つ Preview には、本番とは別のコンテナと Durable Object が自動で用意される。preview で試した内容が本番のコンテナに混ざることはない。Cloudflare のドキュメントでは、Preview でのコンテナ対応は「部分的（partial）」とされているので、うまく動かないときは 9章を参照する。

8参考：リポジトリに置く Cloudflare 用の設定

Workers Builds は、リポジトリのルートにある次のファイルを見てビルドとデプロイを行う。Backlog.md 本体のソースは変えず、コンテナの中で Web UI を起動するための設定だけを足している。

ファイル役割
wrangler.jsoncWorker の名前、コンテナの設定、Preview 用の設定
cloudflare/worker.ts受けたリクエストをすべてコンテナに転送する Worker
DockerfileBun のイメージにソースを入れ、Web UI を起動するコンテナの定義
.dockerignoreコンテナに入れないファイル
package.json開発用の依存に wrangler（4.135.0 以上）と @cloudflare/containers を追加
// wrangler.jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "backlog-md",
  "main": "cloudflare/worker.ts",
  "compatibility_date": "2026-11-01",
  "containers": [
    { "class_name": "BacklogContainer", "image": "./Dockerfile", "max_instances": 1, "instance_type": "basic" }
  ],
  "durable_objects": {
    "bindings": [{ "class_name": "BacklogContainer", "name": "BACKLOG" }]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["BacklogContainer"] }],
  // Preview は本番の設定を引き継がないので、同じ内容をもう一度書く
  "previews": {
    "containers": [
      { "class_name": "BacklogContainer", "image": "./Dockerfile", "max_instances": 1, "instance_type": "basic" }
    ],
    "durable_objects": {
      "bindings": [{ "class_name": "BacklogContainer", "name": "BACKLOG" }]
    }
  }
}
// cloudflare/worker.ts
import { Container } from "@cloudflare/containers";

export class BacklogContainer extends Container {
  defaultPort = 8080; // コンテナ内で待ち受けるポート
  sleepAfter = "10m"; // 10分アクセスが無ければ止める
}

type Env = {
  BACKLOG: { getByName(name: string): { fetch(request: Request): Promise<Response> } };
};

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    // 全員が同じ1台のコンテナを見る
    return env.BACKLOG.getByName("main").fetch(request);
  },
};
# Dockerfile
FROM oven/bun:1.4.4
RUN apt-get update \
 && apt-get install -y --no-install-recommends socat \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY . .
RUN bun install --frozen-lockfile --ignore-scripts
# コンテナには .git が無いので、git を使わずファイルだけで動かす
RUN bun src/cli.ts config set filesystemOnly true \
 && bun src/cli.ts config set remoteOperations false
EXPOSE 8080
# Web UI は 127.0.0.1 でしか待ち受けないため、socat で 8080 番から中継する
CMD ["sh", "-c", "bun src/cli.ts browser --no-open --port 6420 & exec socat TCP-LISTEN:8080,fork,reuseaddr TCP:127.0.0.1:6420"]
# .dockerignore
.git
node_modules
  • socat で中継する理由：Backlog.md の Web UI はソースコードで待ち受けアドレスが 127.0.0.1 に固定されており、コンテナの外（Worker）からは届かない。ソースを変えずに済むよう、コンテナ内で 0.0.0.0:8080 → 127.0.0.1:6420 に中継している
  • --ignore-scripts：bun install 時に husky が git フックを設定しようとして、.git の無いコンテナ内で失敗するのを避ける
  • max_instances: 1：同時に動かすコンテナを1台に抑え、料金がかさまないようにしている
💡 自分の fork に設定が無いとき Codespace のターミナルで bun add -d wrangler @cloudflare/containers を実行し、上の4ファイルを作ってコミット・push する（bun.lock も一緒にコミットする）。ファイルの作成はローカルの Claude Code に「cloudflare.html の8章の構成で Cloudflare 用の設定を作って」と頼んでもよい。

9トラブルシューティング

症状対処
ビルドが「Worker name が一致しない」旨のエラーで失敗する手順2 で付けた Worker の名前と、wrangler.jsonc の "name" が違う。どちらも backlog-md にそろえる
Containers が使えない旨のエラーで失敗するWorkers Paid プランに登録していない。手順1 の「Workers Paid プランに登録する」を行い、ビルドを再実行する
ビルドで wrangler preview が見つからないpackage.json の wrangler が 4.135.0 より古い。Codespace で bun add -d wrangler@latest を実行してコミット・push する
URL を開くとしばらく待たされる／エラーになるコンテナの起動中。初回デプロイ直後は数分かかることがある。数十秒おいて再読み込みする
preview の URL が開かない手順4 で Enable Preview Builds にチェックが入っているか、preview ブランチのビルドが成功しているかを確認する。Preview のコンテナ対応は部分的とされているため、解消しないときは講師に相談する
ログインのコードがメールで届かない入力したアドレスが許可したドメインと違う（許可されていないアドレスでも「コードを送信した」と表示される）。迷惑メールフォルダも確認する。コードの有効期限は10分で、再送すると前のコードは使えなくなる
Access のログイン画面にメールアドレスの入力欄が無い手順3-2 の One-time PIN を追加していない。Zero Trust の Integrations → Identity providers で追加する
Web UI の内容が自動で更新されないWorker の Access は WebSocket を通さないため（手順3-4 の注意）。ページを再読み込みする
GitHub のリポジトリが一覧に出ないGitHub App のインストール時に fork を選んでいない。GitHub の Settings → Applications → Cloudflare Workers & Pages の Configure で、Backlog.md-handson へのアクセスを追加する

10後片付け

  • preview を消すとき：preview ブランチを削除しても Preview は残る。Worker の画面の Previews 一覧から削除する
  • Worker を消すとき：backlog-md の Settings の最下部から Delete する。コンテナも一緒に消える
  • Access の設定を消すとき：Zero Trust の Access controls → Applications と Policies から、手順3 で作られたものを削除する。Zero Trust の Free プランは無料なので、そのまま残しておいてもよい
  • Workers Paid プランを解約する：プランは月単位で課金が続く。Workers & Pages の Plans から Free に戻す
  • GitHub App を外すとき：GitHub の Settings → Applications → Cloudflare Workers & Pages から Uninstall する
✅ ここまでできれば fork の main と preview が、それぞれ自分の workers.dev の URL で、ログインしたチームのメンバーだけに公開されるようになった。Section 3 では、PR ごとに Preview の URL で動作を確かめてからマージする流れを体験する。
